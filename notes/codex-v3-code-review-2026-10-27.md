## 一、总体结论

**代码质量：高。可以进入成人验收阶段，但还不能给孩子用。**

- 数据层（store.py）设计严谨：SQLite 事务 + 乐观锁版本检查 + 操作幂等（重放回执）+ 墓碑删除 + 备份恢复防复活，日志/事件不可原地改写，更正走原子撤回 + supersedes。这是生产级的本地状态管理。
- 边界纪律罕见地好：工具只暴露 8 个窄接口；无路径/shell/网络；身份绑定在进程启动参数；模型自证 `speaker_confirmed` 不被当作物理身份；儿童工具禁止声明成人已核验来源。
- 诚实文化贯穿文档与代码：不声称锁机、不声称平台遗忘、报告更正带 supersedes、"输出文本≠已保存"。
- 测试是真的：MCP 测试拉起真实 stdio 子进程验证工具清单、固定绑定和拒绝路径；有 TDD 痕迹（先失败后实现）；CI 三系统（Ubuntu/Windows/macOS）通过，连"干净 git 归档复验"这种冷门但真实的坑（record-contract.md 被 .gitignore 漏掉）都补上并回归。

## 三、发现的问题

### P1-1　"完成开发"与真实状态之间有距离（信息性，最重要）

代码完成了，但按项目自己的定义，**这不是"整个项目完成"**：

- G01–G10 平台验收全部"未核实"：WorkBuddy 规则/Skill 实际加载、自动记忆关闭、图片/语音链路、OS 隔离、Windows/手机端——一项都没跑过（Codex 自己的 CAPABILITIES.md 如实标注）。
- T01–T42 真实模型情境评测全部 not_run。
- PR #1 未合并；main 分支上没有代码。
- 唯一阻碍实机验收的因素：需要家长在 Mac 上切换到孩子的专用账号配合操作（Codex 记录"家长后续回复暂不方便切换"）。

**给家长的翻译**： Codex 交付的是"可验收的成品包 + 诚实的未验清单"，下一步是家长配合做成人验收（预计 1–2 小时），不是孩子直接上手。

### P1-2　赛马机制被改变了，家长应知情

原计划（workbuddy/README.md）：codex/ 独立写一版 → final/ 综合两版并逐条注明取舍。实际：Codex 直接产出 final/，CHANGELOG 自述"不是另一个已实现版本的独立赛马结果"。整合质量很高、取舍表写得清楚，但**流程与原始约定不同**，且 main 上的 workbuddy/README.md 赛马规则未同步修订。建议家长确认接受这个改变（我认为可以接受——Codex 的方案稿本身已是重大改写，不是 Kimi 版的复制品）。

### P1-3　147 条精选书目知识在工具层被"降级"了

`reading_materials` 工具只暴露**原始目录**（书名+作者+"待核"标记），book-knowledge 库里 B 级条目的 gist/孩子入口/边界话术**没有接入** W-B 工具。这是保守的安全取舍（与"旧库 unread 不导入为个人事实"的纪律一致），但相对 Kimi 开发计划是功能回退：伙伴引书时没有"这本书讲什么、从哪聊起"的可用素材。建议补一层：B 级条目作为"引读话术层"接入 MaterialLibrary（C 级保持仅定位）。

### P2-1　MCP 启动时 prune 的幂等表膨胀

mcp_server.main 每次启动用随机 operation_id 执行 prune——operations 表只增不减，每次启动留一条 startup-* 记录。长期运行会累积。小修：startup prune 用按日期固定的 ID。

### P2-2　时段提醒时区写死 UTC+8

与"当地 7:30–21:00"表述在搬家/出差场景不符。CAPABILITIES 已如实标注"固定北京时间"，家庭常住重庆无实际影响。可参数化或在部署文档写明即可。

### P2-3　晨间提醒文案

outside_window 在 7:30 前也触发"现在到休息时间了"，文案对早晨略怪。非必须改。
