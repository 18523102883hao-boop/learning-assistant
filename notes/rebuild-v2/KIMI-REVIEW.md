# 与 Kimi 方案相互审视：采纳与改写记录

日期：2026-10-26。初始基线提交 `a5380b66d2f80ba67cd3233b124cb28567e640ce`，另纳入 `726df2b508deba3cb1d978f94455d12be666c4e9` 的书架增量。范围：`notes/master-proposal-2026-10-26.md`、路线/产品调研、`workbuddy/kimi/`、`schemas/`、`profiles/`、`HANDOFF.md`，以及新增书架清单和本地8张原图。这是对文本、图片和接口设计的审视，没有运行或实测配置。

当前人类用户的直接说明优先：先讨论功能，不开发不部署；WorkBuddy 双账号先行，网页备用；伙伴平等；阅读核心；不做口语跟读和检查作业。旧文档“已确认”“正式定稿”“马上赛马”的说法不自动构成本轮开工授权。

## 1. 保留的地基

- 平等伙伴的定位，支持不同意、纠错，不做应声虫。
- 首轮及时帮助，允许升级提示、看图/同类例题；不以“启发式”为由一直反问。
- 学习证据与掌握摘要分开；记录真实尝试，不输出人格或动机标签。
- 两账号、各自档案、共有教学原则；周报可导出 Markdown。
- 阅读伙伴优先连接家中藏书，并支持家长未来补充课程与书籍。
- 没有真实验证之前不宣称教育效果；原型配置与正式产品区分。

## 2. 关键差异与修改

| 旧设计/表述 | 审视结果 | v2处理 |
| --- | --- | --- |
| 双账号“彻底解决”混用 | 解决同账号画像问题，不替代资料、路径、跨端与导出的验证 | 改为降低特定风险，列出验收门槛 |
| 自建网页每条软肋“不存在”、天然稳定安全 | 控制点可设计，但实现错误仍可能串档；远程 API 仍处理内容 | 改为可实施控制+测试+备份，不做绝对保证 |
| 后端 system prompt 可强制不代做 | 能保护服务端规则不被客户端直接修改，不能保证模型内容行为 | 区分权限/工具的确定约束与生成内容的概率性约束 |
| 现有订阅直接填 key 即用；月成本个位到几十元 | 未指定套餐、模型、上下文、图片/语音、重试，无有效预算依据 | 正式 API/权益核对后再估算；WorkBuddy先看实际用量 |
| 前3次必须先兴趣再作业 | 孩子可能第一次就急着问作业；容易用喜欢的内容主动发散 | 按当前意图即时服务，形象/称呼可选，不设教学前置旅程 |
| “先情绪后事情”固定第0级 | 对明显受挫有价值，但“不会”不必然是情绪危机 | 简短回应+直接有用帮助并行，孩子选择继续/暂停 |
| 所有输出只可“描述+提问” | 会阻止正常概念解释、纠错、证据判断与自然聊天 | 禁羞辱/人格标签，允许有理由的反馈、直接解释和不提问的回应 |
| 疲劳时“留一个口算” | 把思考都做完只留算数仍可能代做 | 留下有意义的判断、方法或表达；不够时可暂停 |
| 5:1积极沟通、固定15/25分钟、ACE不可替代 | 课程主张的适用范围与证据需校准，不能机械执行 | 原文留档，采用具体尊重/难度适配/可暂停，不设普适数字或未来保证 |
| 教育“永远隐形” | 可以自然嵌入方法，不能隐瞒工具目的、记录或伪装真实生活 | 对方法轻量，对AI身份和数据透明 |
| 兴趣闲聊=情感账户、姐姐是家庭KOL | 关系比喻不应导出依恋或家庭增长指标 | 认真回应但不经营情感依赖，两人各自反馈同等重要 |
| 只收口一次后无限继续，作业后果全归孩子 | 工具若持续引诱发散，也对问题有贡献；自然后果不能变成放任或惩罚 | 聚焦时约束伙伴自己的主动性，停任务/换场景明确，家庭约定可复议 |
| 阅读时“伙伴自己也在读/偶然想起某页” | 没有访问来源就属于伪造经历或内容 | 只基于已见资料分享，不确定时请孩子提供一页或承认不了解 |
| 阅读阶梯 picture→bridge→text→adult | 形式和阅读能力不是同一条等级；图画书可终身读 | 记录文本特征与个体体验，不给儿童排序 |
| 购书次数、首次纯文字完读是核心 | 容易变成促销与完读压力 | 主指标是愿意尝试、接续与理解，购书/完读只作可选事件 |
| 4F固定顺序聊读后感；一天3页 | 方法可以参考，但对话不必成为表单或义务 | 幕后一次选一个问题，阅读节奏由孩子决定 |
| 一律禁止询问读到哪里 | 为避免剧透/找到同一段，有时必须知道位置 | 可直接询问并解释用途，允许“不想说”；不拿页码考核 |
| 收到书只改一个 status，wants→reading | 到货、所有权、阅读与各人状态混为一谈 | 分开书目、家中持有、采购、个人阅读状态与跟进意愿 |
| 不推荐超出阅读阶梯两级 | 没有可验证的分级量尺 | 以兴趣、语言、背景与实际试读感受判断，提供支持或换书 |
| 7日回访率 + 迁移率作为家庭北极星 | 两人样本难形成有意义的留存率，且阅读闲聊不都需迁移题 | 记每人具体自然使用、反馈和独立表现，不用百分比催使用 |

## 3. 已发现的接口/数据问题

这些问题说明旧配置还不能直接视为可部署成品：

1. `learning-event.schema.json` 的 `subject` 只允许语文/数学/英语/跨学科；`learning-log` 要写 `partner_chat`，`reading-companion` 要写 `reading`，不符合该枚举。
2. `learning-log` 声称 `scene_type` 必填，schema 没有定义或要求该字段；当前 schema 允许其他属性，因而也无法验证其合法值。
3. `partner` 只记场景计数并省略其他字段，与 schema 必填的 `attempt_summary`、`hint_level`、`outcome` 等冲突。阅读实际想保存摘要，却与“闲聊不记内容”混在同一分类中。
4. `hint_level=4` 定义成“换讲法后完成”，混合帮助方式和结果；“第0级情绪接收”又与“0=独立完成”口径冲突。v2应分别记录帮助方式、强度和结果，不让数字同时表示不同含义。
5. `evidence_ref` 可空，schema描述已正确要求周报引用时可回查；这不是遗漏原则或必须把所有事件字段改成必填。后续实现仍须落实该约束：无来源事件不能形成确定掌握结论，可回查也不等于结论正确，AI错讲后要撤回相关判断与派生摘要。
6. 书架 schema 的共有书只有一个 `status`，无法同时表达姐姐读完、妹妹未读；到货与阅读也没有分开。
7. 示例档案的 `confirmed_by_child` 实际内容来自家长描述，字段注释也承认未确认；来源应改为 `parent_reported`，不能因为字段名就当成孩子已确认。
8. “示例/含虚构字段”内混有真实家长排名和性格担忧，不能整体视为合成测试数据，更不应自动注入孩子上下文。正式部署要做字段筛选和来源确认。
9. 文件更正被设计成追加事件，但“删除/忘记”不能只追加一句忘记；应同时处理可召回摘要、索引、导出、平台记忆及可解释的备份边界。

本轮仅记录修复要求，未修改历史 schema 和 Kimi 配置；配置改写在功能确认后进行，并须配套语义验收。

## 4. 伙伴体系22条的处理覆盖

| 原条目 | v2去向 |
| --- | --- |
| A1 倾听优先 | 保留倾听，去掉“问永远多于告知”的数量规则 |
| A2 温柔有边界 | 保留尊重和可解释约定，AI不承接父母的爱/管教职责 |
| A3 5:1回应快看 | 保留回应，删除婚姻研究比例向儿童AI的外推 |
| A4 拒绝/沉默 | 保留，可暂停、可不解释 |
| B1 小处开放提问 | 按需要使用，作业时不以问卷开场 |
| B2 请教式开门 | 允许真诚请教，不假装不懂来操控孩子，也不把她总说成专家 |
| B3 具体赞美 | 描述具体发现与修改，不替孩子推定“你一定很得意” |
| B4 同理三层 | 简短、暂定地理解，不读心，不必每次完整走流程 |
| B5 不羞辱 | 保留，同时允许明确纠错 |
| C1 过程反馈 | 保留策略与尝试，允许任务难度/环境等多因素解释，非一律归努力 |
| C2 情绪/ABC | 只用日常辨别事实与想法；不做临床测验、投射解释或治疗 |
| C3 抗逆 | 需要时陪伴与下一步，不以“再努力”包办原因 |
| C4 成长思维 | 伙伴诚实改错，不给孩子脑内角色或人格标签 |
| C5 有效支持 | 保留支持与自主；帮助完成当前作业本身并非不正当初衷 |
| C6 小目标 | 孩子参与，可调整，不让仪式或庆祝成为必须兑现的压力合同 |
| D1 心流 | 保留少打断与合适挑战，去掉按年龄硬切时长 |
| D2 4F | 阅读/作品的可选提示，不固定问序 |
| D3 深阅读与说写 | 保留口述/表达、选择精读，非每本都摘抄/写作 |
| D4 传记 | 自选类型之一，不以名人或“格局”压过孩子当前兴趣 |
| E1 善良助人 | 鼓励现实互助，尊重拒绝，不以神经递质解释人格或要求讨好 |
| E2 契约 | 双方参与、可复议，不采用惩罚和故意放任失败 |
| E3 ACE | 作为值得发展的能力，不宣称AI永远不能替代某能力 |
| E4 好奇 | 保留，一起核查，不编资料 |
| F1 创造游戏 | 探索时自选，不在作业期间主动投放 |
| F2 情绪词 | 可提供候选，不断言真实感受 |
| F3 支点科目 | 按实际小成功找起点，不把一次表现写成固定优势 |
| F4 积累游戏 | 可选，不设固定每天词数和补卡要求 |

原文标题说22条，但其表格标签实际共27项（A4+B5+C6+D4+E4+F4）；本表按全部标签逐一处理，不以原标题计数替代覆盖。全量原文读完之后的课程发现另见 `research/`，并不以这27项为阅读边界。

## 5. 产品调研的校准

旧深度调研中的市场价格、机型定位、行业第一、一次买断免所有服务费、品牌商业动机等，不作为本方案依据。厂商功能页只能支持公开说明的功能与适用范围，不能支持“行业已验证”或“用户一定喜欢”。

讯飞官方脚注将某些规划/追溯能力限定于初中数学；不能笼统转成三、五年级可用。保留来源充分的设计机制，缺少实机路径的部分标为待验证。详见 `research/product-and-platform-facts.md`。

## 6. 对新增书架成果的评价

`library/bookshelf.json` 已把照片与家长补充汇成39条目录，显著降低了从零建书架的成本，值得保留。我们完整读取清单并逐张查看8张原图，主要书脊大体对应。具体核验见[书架复核](research/bookshelf-review.md)；这里不把目录条数当独立册数、原图核对当书内全文阅读。

必须调整的是状态和推断：全部`unread`不能当成两孩子真实未读，`owner`不能当排他归属，`transition_level`不能当能力排名，`interest_hook`不能自动变成伙伴指令。尤其“作业救急顺手引数学史”“教材配套的天然购书位”会重新引入分心与促购。明确误识别包括bk-0021：图中《要是你给小狗吃甜甜圈》被记成《要是你给老鼠吃饼干》。保留原清单，配置前做带来源、未知状态与集合层级的版本化迁移，不全盘丢弃，也不直接加载为事实。

总体评价：Kimi已提供有价值的产品骨架、可供讨论的场景和初始资产；现有提示词及数据接口仍需改写与成人验收。v2继承其伙伴定位、及时帮助、记录证据、阅读和书架方向，重做强制流程、关系增长指标、阅读等级和未验证技术承诺；不是宣布旧版毫无价值，也不把新文本视为已验证产品。
