## 需处理的问题

### PM1 — P1：正向学习价值缺少可以体验和验收的锚点

- 文件段落：`PROPOSAL.md` §1、§3、§8、§11；对照旧 `workbuddy/kimi/skills/explore-task/SKILL.md` 的两个启动任务，以及 `research/product-and-platform-facts.md` §1“真实任务的乐趣”。
- 具体场景：孩子问“学数学有什么用”，或想把一页漫画、一个家庭小游戏做得更好。主稿有“作品由孩子决定”的原则，却没有展示语文、数学、英语如何在真实目标中派上用场。后续 AI 可能只学会少问、少夸、不跑题，却仍给出平淡的辅导与书目管理。
- 风险：产品可以通过一长串禁止项检查，却没有体现家长要的学科意义、游戏乐趣和逐渐敢于尝试。若用夸赞、剧情奖励补这一空白，又会偏离定位。
- 最小修正：在主提案补 2–3 个可选的短场景，展示“孩子自己的目标→一个有后果的动作→按需用到知识→她作出修改或选择”。例如比较漫画两种对白怎样影响读者理解；试两种计分规则并找不公平的例子；为自己的作品写一句真实有用途的英文说明。保留旧探索 Skill 中可取的真实任务，不继承其强制结束复述。试用观察孩子是否能说出或表现出某个知识帮了什么、是否愿意自己改一处；不生成“自信提升分数”，也不在每次作业后追加任务。

### PM2 — P1：四种使用意图明确，首轮可交付切片仍不明确

- 文件段落：`TECH-ROUTE.md` §3“统一内核与局部能力”、§4 十类数据概念与家长汇总；`DEVELOPMENT-HANDOFF.md` 阶段A–D；`PROPOSAL.md` §11。
- 具体场景：后续开发者按阶段A清单一次准备六个 Skill、书目版本、共有藏书、两人阅读状态、采购、提醒、学习记录和家长报告，无法判断什么时候已经足够让成人演练、哪些能力可以人工维持。
- 风险：数据概念被误当成首批必须建成的完整系统；配置工作膨胀，最关键的帮助与陪读迟迟没有真实反馈。反向压缩时，又可能照旧版只上作业，丢掉阅读核心与普通伙伴体验。
- 最小修正：增加一张首轮交付表，逐项标明“必须可用的基本行为 / 成人可手动处理 / 后续再自动化”和验收证据。首轮保留作业求助、当前页面陪读、自由聊天与自选创作的基本响应；只录少量已确认书目，愿望单与两份摘要可由成人维护。全量书架、跨端自动同步、定时跟进、自动跨账号汇总不应被隐含为儿童开用前提。列清成人日常与每周要做什么；人工搬运若影响每次使用，应当重评路线。先验收一条完整闭环，再扩大覆盖，不以文件数量作为完成标准。

### PM3 — P1：单步题与连续多轮求助仍缺“不代做”的边界样例

- 文件段落：`PROPOSAL.md` §5 第4、6条及“对当前作业不交付整题代做”；`DEVELOPMENT-HANDOFF.md` 阶段C。
- 具体场景：孩子问“这一步为什么要除以3”，或一道作业本身只有一个关键判断。直接讲清这一点可能已经接近完整解答，没有自然剩余步骤可留。另一端，多步题每轮只教一步，也可能累积成 AI 做完整题。
- 风险：模型为保留“有意义动作”制造猜谜或额外练习；或者逐轮完成全部推理，再把最后抄写当作孩子思考。第一轮的帮助升级原则正确，但这两端仍无法稳定执行。
- 最小修正：补三个正反样例，分别覆盖“已有答案、求解释”“尚未作答的单步题”“多步题连续要求继续”。明确概念、定义和孩子已提供结果的理由可以讲清；帮助按整段对话判断，不能以每轮一步证明没有代做。没有自然剩余动作时，不制造口算或变式门槛，不虚报独立完成；把实际示范到哪一处记为辅助。当前待提交单步题可以讲到什么程度，应在样例中作出具体产品选择，不能留给每个 Skill 临场猜。

### PM4 — P1：平台前提还需要变成逐项开用判定

- 文件段落：`TECH-ROUTE.md` §1–2、§5；`DEVELOPMENT-HANDOFF.md` 阶段B第1、4、5、7项；`research/product-and-platform-facts.md` §2。
- 具体场景：文档已证明 App 存在拍照、语音和多端入口，成人便认为 Mac/Windows 的实际路径也已过关；或者能登录两个账号，就忽略项目规则加载、全局权限、平台记忆和摘要出口。交接第B1项“必要时核对国内注册和监护安排”还可能被理解成可选。
- 风险：证据等级混用。官方介绍某功能，不能证明家庭设备上的完整路径、两个账号的使用安排或所需权限边界已经满足。
- 最小修正：在配置验证阶段保留一张判定表，按账号、设备、执行模式记录“官方有说明 / 成人实测通过 / 未通过 / 未核实”、证据和处理决定。纸题全链路、身份与私有资料、必要工具权限、记忆更正/删除和约定摘要出口均须有结论。国内实际注册及监护安排的核对是儿童直接使用前的必办项，记录所核对版本与日期，不预设允许或禁止。关键项未知或失败时不标为儿童可用；可接受的人工替代也须实际跑通。不能让孩子在使用中打开完全访问来补缺口。

### PM5 — P1：AI 纠错没有与学习证据和已生成摘要闭环

- 文件段落：`PROPOSAL.md` §8–9；`DEVELOPMENT-HANDOFF.md` 阶段C“AI原解释确实错了”、§4；`TECH-ROUTE.md` §4。
- 具体场景：AI 把一道题解释错，孩子按错方法完成，事件已记为“辅助下完成”，周报已据此写“用图示理解了分组”；后来孩子或成人发现是 AI 的错误。
- 风险：伙伴当场认错了，旧事件和派生摘要却仍成为下一次辅导或家长判断的依据；甚至把 AI 造成的错误归为孩子持续卡点。只有事件 ID 并不能证明事件判断正确。
- 最小修正：规定一个最小纠错链：原记录标为有误或待核实，停止把它用作确定学习结论；关联更正依据，重算未分享摘要，已导出报告明确有版本更正可供家长替换。记录实际尝试者、帮助量和结果判定来源，区分孩子自报、会话可见过程、成人观察与模型判断。无需保存整段私人原文，也不能由模型生成题目后自行宣称儿童已完成验证。把这一链加入成人语义验收。

### PM6 — P1：恢复与迁移要求主要落在网页阶段，WorkBuddy 首次开用仍缺恢复闭环

- 文件段落：`PROPOSAL.md` §2 仅覆盖输入失败；`TECH-ROUTE.md` §4、§6、§7；`DEVELOPMENT-HANDOFF.md` 阶段B第6项与阶段E。
- 具体场景：电脑睡眠或额度耗尽打断讲题；记录只写了一半；孩子更正已生效却从旧备份恢复；平台更新后无法续接，决定迁移网页。
- 风险：孩子不知道题目停在哪里，重试重复记成功；家长拥有一堆文件却不能恢复；迁移把撤回的信息、错误学习结论或姐妹状态再次带入。仅承诺“可导出”还不等于可以恢复使用。
- 最小修正：把一项成人恢复演练提前到 WorkBuddy 开用前：用虚构档案中断一次，再从最后确认的任务状态与有效记录恢复。向孩子提供简短状态和明确重试/暂停出口，失败不假装完成，维护由成人承担。约定可迁移最小包包含当前伙伴规则版本、有效个人事实、任务暂停点、书目与个人状态、可分享摘要及其来源；保留更正/撤回效果。说明哪些平台历史或媒体无法导出。迁移先用虚构包导入核对身份与权限；关键隔离或权限失败应先停止对应儿童入口，再重评路线，不能等待多次真实损失后才处理。

### PM7 — P1：新书架候选目录缺少进入 v2 的准入规则

- 文件段落：新增 `library/bookshelf.json` 全部39条，尤其 `bk-0009`、`bk-0020`；`library/README.md`“唯一需要做的”；`PROPOSAL.md` §7.1、§7.4；`TECH-ROUTE.md` §4。
- 具体场景：后续 AI 看到已经存在的 JSON 就直接加载。所有条目 `status=unread` 被当成孩子真未读；`owner` 被当成只能推荐给某个孩子；`transition_level` 变成能力等级；`interest_hook` 中“作业救急顺手引学科史”“买书闭环天然推荐位”又成为行动指令。系列/套装一条被当成一本完整版本。
- 风险：v2 的原则在导入真实资产时被绕过，已有读过的书变成欠账、推测变事实、作业又被主动发散。照片现已可查看，仍不能证明书内情节、具体难度和孩子阅读状态。
- 最小修正：明确39条是带来源的候选目录，旧 JSON 保留；配置前先输出迁移映射。把持有、个人阅读状态、来源与确认分开，`unread` 初始值迁为未知而非真实未读；套装保留集合层级，单册和版本按实际需要补齐。`owner` 与兴趣要保留其家长报告/推断身份，不能限制另一孩子；删除等级式推荐规则。`interest_hook` 只能作为待核验的设计建议，不能作为常驻行为指令。先采用少量核对后的书目，并允许随时拿未登记页面来聊。此项是新增目录的导入问题，不是重复要求修旧 schema。

### PM8 — P2：“仅显式求书才荐书”关闭了一部分自然阅读发现

- 文件段落：`PROPOSAL.md` §7.2；与§6 作业聚焦、§8 兴趣交流共同阅读。
- 具体场景：自由聊天时孩子主动对一个真实现象或故事背景产生好奇，但她不知道家里哪本书能回应，因此没有说“推荐书/查资料”。伙伴严格遵守当前“仅当”条件，所有自然连接都被挡住。
- 风险：修正自动荐书过度后，又把阅读变成必须先有清楚检索意图的服务，损失家长希望的自然引读。反过来，放宽成“只要聊兴趣就荐书”会重现 C3。
- 最小修正与产品判断：建议保留一个窄例外——**非作业场景，孩子自己提出具体好奇，伙伴先回应当前内容，且有可靠相关书目内容时，可偶发给一个可轻松拒绝的阅读入口。** 一次最多一本、一个理由；孩子拒绝或略过就继续原话题，不追问、不留任务、不写成未完成事项。普通漫画聊天仍无需转书，不能用悬念吊住、伪造“我刚读过”，也不暗示漫画低一级。试用应观察孩子是否感到自然、有帮助、可忽略；不能把转荐书次数当成功指标。“润物无声”应体现在节奏与选择权，不能意味着隐藏教育目的或记录。

### PM9 — P1：v2 交接边界清楚，根入口仍会把下一位 AI 引向旧开工指令

- 文件段落：根 `README.md` 当前阶段、交接与设计要点；根 `HANDOFF.md` §4；`workbuddy/README.md` 赛马规则与部署步骤；对照 `notes/rebuild-v2/README.md` 与 `DEVELOPMENT-HANDOFF.md` 开头。
- 具体场景：下一位 AI 只从仓库根 README 进入 HANDOFF，看见“第一件事写 Codex 版”“两版各绑一个孩子跑 A/B”和旧配置部署步骤，尚未发现本轮禁止实施的新交接。
- 风险：已经足够清楚的 v2 限制无法在检索入口生效；旧冷启动、指标、固定规则和注册假设被当作当前授权重新执行。
- 最小修正：在三个根入口顶部增加醒目的当前状态与 v2 入口，说明旧文档及 `workbuddy/kimi/` 是历史材料，本轮只有方案讨论与修订授权。历史正文可保留。新交接继续区分“功能建议被认可”与“明确进入某个配置/开发范围”；不能把本报告或文件清单当作实施授权，也不必为已授权的日常文字修订另设审批流程。协调方已表示会统一补入口指针；此处记录的是本次快照仍存在的问题。

## 推荐处理顺序

先处理 PM9 的当前入口和 PM7 的新增资料含义，避免后续 AI 读错事实或阶段。再把 PM1 的正向价值与 PM2 的首轮切片一起写清，随后用 PM3 的边界样例检验帮助规则。PM4、PM5、PM6 是未来成人配置验证与儿童开用前的证据要求，本轮只完善规格，不运行。PM8 可以随本次功能修订落实，但其体验结论仍须由两名孩子分别提供。

两账号、默认不提醒、家长摘要和可退出是支持条件；孩子喜欢还需要知识确实帮上忙、表达被认真理解、作品与发现属于她自己。减少使用、拒绝一本书或不想继续都应被接受，不能把它们自动解释成产品失败或儿童缺乏动机。
