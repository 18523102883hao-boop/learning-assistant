# 技术路线决策：自建网页版 vs WorkBuddy

日期：2026-10-26。问题来源：家长 2026-10-26 的原始提问（Codex 额度耗尽前最后一个未回答问题）——"给孩子直接打造一个网页版（后台接入我订阅的模型），拟人化形象、两个账户，家里两台电脑（MacBook Air + 小米 Windows）一人一台。哪种更好？要成熟稳定、可控。"

## 结论（建议）

**采用方案 B：自建网页版作为正式形态；WorkBuddy 并行小成本验证教学对话即可，不必作为长期依赖。**

理由：把三个目标按重要性排序——**可控（身份隔离、教学规则可强制、数据私有）> 成熟稳定 > 快速上线**。WorkBuddy 赢在快速上线，但恰好在"可控"上有三个未验证的软肋；自建网页版的每一条软肋都不存在，且所需技术非常成熟。

## 方案对比

| 维度 | A. WorkBuddy 原型 | B. 自建网页版（推荐） | C. ADP / Dify |
| --- | --- | --- | --- |
| 双账户身份隔离 | ⚠️ 两个孩子共用成人账号，自动记忆未见工作区隔离承诺；身份靠提示词声明 | ✅ 服务端账户体系，天然隔离；学习档案分库存储 | ✅ 按终端用户隔离，但需另行开发前端 |
| 教学规则可强制 | ⚠️ 靠项目指令/Skill，孩子会话可切换、全局配置会合并加载 | ✅ 规则在后端 system prompt 注入，版本化管理；可在服务端校验不代做 | 部分（编排层约束） |
| 拟人化儿童界面 | ⚠️ 通用聊天 UI，儿童入口未验证 | ✅ 完全自定义：角色形象、大按钮、语音/拍照入口 | 需自建前端 |
| 数据私有 | ⚠️ 内容进第三方平台与记忆系统，儿童条款未核实 | ✅ 学习事件存本地/自有数据库；API 只传当前对话 | 取决于部署（Dify 可自部署） |
| 多模态入口（拍题/语音） | ✅ 现成（小程序支持图片/语音） | 🟡 需自己做：图片上传 + 多模态模型识别；语音可用浏览器 API / 模型 ASR | 视渠道 |
| 成熟稳定 | ✅ 平台托管 | ✅ 技术栈成熟（React + FastAPI + OpenAI 兼容接口），家庭规模无并发压力 | 中等 |
| 上线速度 | ✅ 最快（配置即用） | 🟡 需开发（MVP 约 1–2 周业余时间） | 慢 |
| 维护成本 | 低 | 中（家庭场景量级小） | 中高 |
| 未成年人条款风险 | ⚠️ 共用成人账号，需核实儿童使用条款 | ✅ 家庭自用，无平台条款问题；隐私责任自担 | 中 |

## 推荐架构（方案 B）

```
┌─ 儿童端（浏览器，两台电脑各登录一个账户）─────────┐
│  拟人化助手形象 · 语音/拍照/文字输入 · 帮助按钮      │
│  （"再提示一点 / 看个例子 / 换种讲法 / 我自己试试"）│
└──────────────┬───────────────────────────────────┘
               ▼
┌─ 后端服务（先跑在家用电脑，可后迁云/NAS）──────────┐
│  账户：momo / yiyi（用户名 + PIN，家长设置）        │
│  教学引擎：注入 PROJECT_INSTRUCTIONS + 当前 Skill  │
│  不代做红线：服务端输出校验（整篇作文/整题答案拦截） │
│  学习事件：按 child_id 分文件写入（jsonl，符合 schema）│
│  家长端：周报生成（读学习事件，只写有证据的内容）    │
└──────────────┬───────────────────────────────────┘
               ▼
        模型 API（OpenAI 兼容接口，base_url + key 可配置，
        家长现有订阅；图片题走多模态模型）
```

要点：

- **模型可切换**：不绑定单一厂商，家长已有订阅直接配 `base_url` / `api_key`；多模态模型负责拍题识别（识别不确定时先问孩子确认那一处）。
- **规则与平台分离**：`workbuddy/PROJECT_INSTRUCTIONS.md` 和 4 个 Skill 的内容直接复用为后端 system prompt 与流程状态机，已写好的内容不浪费。
- **MVP 范围**：单任务对话 + 三级帮助 + 学习事件记录 + 家长周报四个接口；不做错题本图形化、不做实时白板、不做 App。
- **拍题识别**：v1 用多模态大模型直接读图（去标识后），识别结果先给孩子确认；不确定时不猜题。

## 与 WorkBuddy 的关系

- 并行不冲突：WorkBuddy 配置草案已就绪（`workbuddy/`），可用于**第一周快速验证教学对话**（孩子是否愿意用、提示节奏是否合适），验证结论直接回流入网页版设计。
- 若网页版 MVP 跑通，WorkBuddy 路线可冻结，验收清单（`validation/prototype-checklist.md`）中"平台隔离"相关条目转为网页版的账户隔离测试。

## 待家长确认

1. 订阅的模型提供商与可用的多模态模型（决定 `base_url` / `api_key` 与拍题识别方案）。
2. 后端先跑在哪台电脑上（MacBook Air 还是小米 Windows）；长期可考虑云服务器或 NAS。
3. 儿童端的拟人化形象偏好（动物/机器人/魔法角色？先选 1 个，孩子试用后可换）。
