## 1. 需求复述与成功标准

### 1.1 家长的原始诉求（从全部提示词提炼，按权重排序）

1. **不给答案，给思路**：引导孩子搞懂知识点，而不是知道答案却不知道哪没掌握。
2. **孩子喜欢用**：用过直接给答案的 AI 工具，担心孩子嫌"不给答案"不好用而放弃；喜爱度是成败关键。
3. **学科意义感**：让孩子明白为什么学语文/数学/英语，在真实任务中体验学科能解决的问题（"先给发动机，再给工具"）。
4. **家长视角**：提炼两个女儿各自哪里掌握不好、是否有学习不认真/走捷径的情况——要求有据可查，不是拍脑袋。
5. **双账户隔离**：姐妹俩的记忆、学情、作品必须分开，不能混乱。
6. **可控、成熟稳定**（对工具本身的要求，技术路线选择的第一约束）。

### 1.2 两个必须同时成立的成功标准

- **接受度**：孩子有需要时愿意自主再来；愿意选探索任务；觉得帮助合适。
- **可迁移**：离开 AI 后，能独立处理换数字/换情境的同类问题；能解释关键步骤的理由。

二者缺一都要改设计：喜欢但不能迁移 → 改教学过程；能学会但不愿用 → 改节奏与交互。**使用时长、连续签到、答题量不作为成效指标。**

## 2. 多维度调研复盘

### 2.1 教学与儿童心理维度（Codex 已完成，我复核认同）

- 帮助逐级增加：目标/条件提示 → 具体提示/图示 → 同类例题演示 → 孩子完成原题关键一步；连续两次未推进换讲法。
- 首轮就给有用帮助，不盘问；孩子已尝试且答错时直接说清错因，不让反复猜。
- 概念、词义、发音、背景可以直接讲——不是所有知识都做成猜谜。
- 反馈描述具体做法，不空泛夸人；不做人格/动机结论（"懒惰""不认真"永不输出）。
- 理论校准：85% 规则、学习金字塔留存率等说法缺乏可靠依据，仅保留为设计假设，由试用验证。
- 家长报告：每周两条具体进步 + 一个待观察卡点 + 一个家长小动作，全部指向证据。

### 2.2 产品交互维度（Codex 调研 Khanmigo/DragonBox/Duolingo/学而思/讯飞/小度）

可借鉴且适合我们的：Khanmigo 的"作答前给提示、答错后明讲+同技能练习"；DragonBox 的"操作先于抽象，结束要翻译回纸笔"；Duolingo 的"解释交给孩子选择，语言放进任务"；学而思的"指哪讲哪，定位到步骤"；讯飞的"轻量定位卡点→微讲解→变式验证"。
明确不借的：排行榜、姐妹比较、断签惩罚、扣生命阻止求助、把使用次数当成效。

### 2.3 平台技术维度（Codex 核验 + 我的路线决策，2026-10-26 晚修订）

- WorkBuddy：Working Memory 按 workspace 独立，但自动个人记忆未见隔离承诺；全局配置会与项目配置合并；未成年人条款未核实。
- **双账户方案（家长提出，已核实可行）**：国内版 WorkBuddy 支持手机号登录，每人可建 5–10 个项目；两个孩子各用自己的手机号注册独立账号，一人一个学习项目，**彻底解决单账号记忆混用问题**——此前我对 WorkBuddy 最大的反对理由被移除。成本：免费体验版每人 500 积分/月（约 200 万 Token），试运行可能零成本；不足时标准版连续包月 70 元/月/账号。
- 拍照/语音输入是孩子的刚需（她们已习惯用 DeepSeek 拍题语音问作业），而这是 WorkBuddy 的现成能力，自建网页版需额外开发——**这是 WorkBuddy 先行的决定性优势**。
- **修订后的路线（v0.2）**：WorkBuddy 双账户**先行落地**，快速用起来；网页版降级为**长期备用路线**，触发条件明确（见 §6 Phase 3）：双账户试用后发现隔离仍不合格、未成年人条款有问题、或孩子需要更简界面而平台做不到时启动。
- ADP/Dify：更后一层的候选，暂不动。

### 2.4 教材维度（Codex 发现风险，我逐科核实）

- 语文：统编教材（人教社），全国统一，已确认。
- 英语：重庆人教 PEP / 重大版 / 外研版并存，大概率人教 PEP 新教材，待封面确认系列册次。
- 数学：**人教版与西师版在重庆并存**，家长记忆对数学可能不准，必须实物核对。当前最大版本风险点。

### 2.5 隐私与合规维度（Codex 已立基线，我补充执行细则）

- 仓库与孩子档案不使用完整姓名、生日、学校；作业照片去标识（裁掉姓名学校）。
- 网页版数据全部自存（学习事件 jsonl 本地保存），不进入任何第三方平台画像。
- 儿童正式使用前，家长核实用到的模型服务商条款中对未成年人数据的处理。
- 姐妹账户分离是服务端强制，不靠提示词自觉（这是对 WorkBuddy 方案的关键升级）。

### 2.6 运营维护与成本维度（Codex 未覆盖，我补充）

- **API 成本**：家庭用量按每天各 20 轮对话、每轮输入 2k/输出 500 token 估算，月成本在个位数到几十元人民币量级（取决于所用模型），不构成决策障碍。
- **维护工作量**：MVP 后每周维护约 1–2 小时（看周报、调提示词、更新档案）；架构上把教学规则做成**独立配置文件**而非写死在代码里，家长可改、Codex 可接手。
- **故障兜底**：模型 API 不可用时不阻断孩子作业——界面明确提示"助手休息了，先跳过这题，回头再问"，不让工具成为作业的前置依赖。

## 3. 独立观点：我与 Codex 一致和分歧的地方

### 一致

教学规则十条、双档案显式管理、报告只写有证据内容、WorkBuddy 不能默认满足隔离——这些 Codex 的结论我复核后全部认同，直接沿用。

### 分歧与补充（按重要性排序）

**3.1 路线：v0.2 修订——接受 WorkBuddy 双账户先行，网页版作为长期备用。**
我最初的判断（WorkBuddy 单账号隔离不可靠，应网页版优先）建立在"两个孩子共用一个成人账号"的前提上。家长提出**两个孩子各注册一个独立账号**（她们已有手机号），这个前提被移除，WorkBuddy 的隔离问题降到可管理范围。叠加"拍照/语音是刚需且为 WorkBuddy 现成功能"，先行的理由变得充分。修订后分工：
- **WorkBuddy 双账户** = 教学验证场（1–2 周跑通"孩子是否愿意用、规则是否生效、记忆是否串档"）；
- **网页版** = 长期备用，触发条件见 §6 Phase 3，方案已预研（`tech-route-decision-2026-10-26.md`），届时不重来。

**3.2 "两次未推进换讲法"这类数字，Codex 写进了规则，我认为应做成可调参数。**
它本来就是一个初始假设。做成参数（hint_escalation_threshold）的好处：试用期间按两个孩子的真实反应分别调，姐姐可能需要 1 次就换、妹妹可能 3 次也没问题；而且调整参数不需要改代码。规则文档里保留建议默认值 2。

**3.3 防"代做"：流程防 > 检测防，要诚实告诉家长技术边界。**
靠服务端正则或二次模型审查拦截"整题答案"既不可靠（误杀讲解、漏杀变形问法）又增加延迟和成本。更实际的是**流程设计**：分步交付、最后一问留白给孩子、作文场景只给结构和提问不给段落。剩余漏网靠家长抽查。家长需要知道：没有任何技术手段能保证 100% 防代做，家庭场景的防线是设计+抽查+信任。

**3.4 语音输入是三年级的"主输入"，不是 v2 功能。**
一一 8 岁，打字速度撑不起"作业救急"场景；语音才是她自然的方式。同时语音识别错误会污染题目理解，所以设计为"语音→文字→孩子确认一遍再作答"。浏览器 Web Speech API 在 Chrome/Edge 上中文可用，Mac 上用 Chrome 即可绕开 Safari 限制。

**3.5 拍题识别：多模态大模型读图 + 孩子确认，不上传统 OCR。**
小学手写体、圈画痕迹对专用 OCR 不友好；多模态大模型对题意理解更好，且"识别结果先给孩子确认"本来就是教学流程的一部分（确认歧义处）。兜底方案：孩子直接口述/手输，零成本永远可用。

**3.6 记忆三层分离，避免"什么都往 prompt 塞"。**
- 本次对话上下文（工作记忆，随会话清空）；
- 学习事件流（jsonl，只追加，可更正，审计轨迹）；
- 掌握摘要（由事件生成，状态机：待观察/辅助下完成/独立完成/延迟迁移成功）。
系统提示词只注入"当前会话需要的最小档案"（昵称、年级、已确认兴趣、进行中作品、近期 3 条摘要），全量历史不进上下文——省钱且减少串档幻觉。

**3.7 "喜欢"和"迁移"要做成产品内可度量指标，不能只靠家长观察。**
Codex 的方案靠两周观察。我建议同时落成数据：再次使用率（求助后 7 天内是否自主回来）、帮助延迟（首轮有用帮助出现的轮次）、迁移验证完成率（隔天换题做对的占比）。周报里自动带出趋势，家长看到的不只是单次描述。

**3.8 家长报告的样本偏差，应在产品内显式提示。**
报告页固定一行字："本报告仅基于孩子来求助的题目，不代表全部学科能力。"防止家长把报告当全景成绩单——这是你最初诉求里最容易被误用的地方。

**3.9 姐妹共用一台电脑的场景要显式设计。**
家里一台 MacBook Air 一台小米本，恰好一人一台，但孩子会串座。账户切换必须是**显式动作 + 家长 PIN**，切换后清空界面上下文；每次会话顶部显示"现在是沫沫的空间"（头像/颜色区分）。这比 WorkBuddy 的"切工作区"可靠得多。

**3.10 探索任务先做"任务卡"模式，不做自由聊天。**
自由聊天让孩子自己找任务，对三年级太难。"我想弄明白"入口给 3 张可选任务卡（结合她的兴趣：漫画工作室/小游戏设计室/生活小项目），她选一张或说"我想做别的"。降低启动成本。

## 3A. 孩子视角审查（查漏补缺）

以两个具体的人——不是抽象的"用户"——把方案走一遍。

**沫沫（10 岁）的典型晚上**：8 点，数学作业剩最后一道应用题，9 点她想画画、看猫小九。她把题目拍给助手。此刻她的内心状态是"赶紧搞定去画画"，不是"求知"。如果 30 秒内没有一个能动手的东西，她切回 DeepSeek；如果助手反问"你觉得呢"，她翻白眼——"我要知道还问你？"；如果连续两轮没进展，她认定"这工具不好用"并告诉一一。她做对一个关键步骤时需要**立刻被看见**（"对，你找到 4 盒了"）——这个正反馈是她的燃料。另外，班级排名三十出头的她对"不会"极其敏感，任何让她觉得"显得笨"的措辞（"这很简单""你再想想""你不是学过吗"）都是致命的。

**一一（8 岁）的典型场景**：直接语音说"这道题怎么做"。她识字量有限、打字慢；自尊心强、要强，被引导"再试试"但试错了，可能生气放弃；她的成功体验来自"闯关赢"，而不是"被辅导"；姐姐用什么她用什么。

由此发现原方案的 8 个缺口：

1. **第一印象没有设计。** 孩子会不会用第二次，在第一次对话的 3 分钟内决定。补上**冷启动剧本**（见 §6 Phase 1）：第一次对话不从作业开始，从兴趣开始——沫沫的开场是"漫画工作室"邀请，一一的开场是"小游戏设计室"邀请；先建立"它懂我、它好玩"，再进入作业场景。**先兴趣、后作业**是本次审查最重要的修正。
2. **场景话术库缺情绪场景。** 现有教学规则覆盖"卡住/要答案/答错"，但真实场景还包括：自我否定（"我不会，我很笨吧"）、对抗（"我就要看答案怎么了"）、疲劳赶时间（"快点我困了"）、防御（"老师没教过！"）。沫沫的自我否定场景必然出现，回应必须保护自尊且不能空洞安慰——每种场景需要预案话术，写入 Skill。
3. **"即时胜利"与"被看见"缺乏具体规范。** 正反馈要快（一步一反馈）、要具体（描述她做对了什么）、要即时（30 秒内有第一个可完成动作）。
4. **成就无法外显。** 孩子喜欢一个工具的重要原因是能拿去展示。"我来讲给你听"的成果生成一张漂亮卡片（这次我独立完成了什么），可以给爸爸妈妈看。补上"成就卡片"。
5. **掌控感清单缺失。** 孩子能自己改什么：助手称呼/名字、主题、提示详细程度、删除自己的记录。列出"孩子说了算"清单并写进产品。
6. **羞耻与隐私场景。** 若在同学面前被看到"还要问 AI"会被嘲笑；记录可能被同学翻到。要求：界面看起来像普通聊天，一键清屏，记录入口藏在家长侧。
7. **一一的输入适配。** 语音为主、按钮文字限她认得的字、避免长句回复。
8. **姐妹动态没有设计。** 姐姐是家庭内 KOL（一一模仿她），姐姐一句"不好用，DeepSeek 直接给答案"就能杀死项目——她的第一次体验必须精心编排（见 §6 分阶段启动）。同时设计姐妹合作任务（互相讲题、共同作品），但个人记录仍分开。

## 3B. 产品经理视角审查（二次复盘）

1. **北极星指标定义。** 不是时长。定为双指标：**7 日主动回访率**（接受度）与**无辅助迁移率**（隔天换题独立做对的比例，学习有效性）。辅以两个过程指标：首轮有效帮助延迟（几轮对话后孩子才得到可用动作）、帮助升级率（是否需要升到 3 级以上）。
2. **MVP 再收敛。** Phase 1 只上**一个入口**（帮我过这一关）+ 冷启动剧本 + 确认环节 + 学习事件记录 + 周报。"我想弄明白"和"我来讲给你听"推迟一周——先证明核心闭环，再扩展。
3. **冷启动即留存。** 前 3 次对话的产品化剧本：第 1 次兴趣邀请 + 认识彼此；第 2 次一道她自选的小任务（可完成、可展示）；第 3 次才自然进入作业救急。三次之内她要经历一次"我自己做成了"。
4. **分阶段启动（staggered rollout）。** 先姐姐单独跑 5–7 天，跑通并让姐姐说出一句"还挺好玩"之后，妹妹再加入。不要同时启动：两个问题孩子叠加会让家长无法归因。
5. **家庭内增长飞轮。** 获客靠姐姐（KOL 效应）；**家长周报是留存工具**——家长看到证据才会持续允许使用；孩子的成就卡片是传播工具。三个角色（姐姐/妹妹/家长）各有一个粘性钩子。
6. **成本监控。** 每周看一眼 WorkBuddy 积分消耗（家长客户端可见），估算月成本，决定是否需要付费版——把"什么时候花钱"变成有数据依据的决策。
7. **定位语句**（对内统一口径）：**"不喂答案的学习搭子"**——区别于 DeepSeek（答案机器）和学习机（刷题诊断机）。所有功能取舍用这句话检验。
8. **运营机制。** 每周 30 分钟"产品会"：家长 + AI 助手（就是我们）复盘周报指标，调整参数和文案。工具不会自己变好，迭代节奏才是产品。

## 4. 功能定义（MoSCoW）

### 4.1 孩子端（Must have）

| 功能 | 说明 | 对应教学规则 |

| 三个入口 | 帮我过这一关 / 我想弄明白 / 我来讲给你听 | 设计稿 §2 |

## 5. 实现方式（定稿后细化）

**Phase 1–2 用 WorkBuddy 现有配置（已就绪）**：`workbuddy/PROJECT_INSTRUCTIONS.md` 粘贴为项目常驻指令；4 个 Skill 导入；`profiles/` 示例档案转为真实（去标识）档案；部署步骤见 `workbuddy/README.md`。

**Phase 3 网页版备用路线（已预研，触发后开工）**：
- 前端：React 单页应用，儿童端与家长端两个视图；语音用 Web Speech API（Chrome/Edge）；拍照用文件上传。
- 后端：Python FastAPI（或 Node，Codex 接手时可议），SQLite 起步，学习事件按 `schemas/learning-event.schema.json` 写入。
- 模型：OpenAI 兼容接口，家长订阅的模型；拍题识别用多模态模型；供应商可换。
- 部署：先跑在家用电脑（局域网内两台机器访问），后续可迁云服务器/NAS。
- 教学规则配置文件化，与平台无关——WorkBuddy 阶段打磨好的指令与 Skill 内容可平移。

## 6. 开发计划草案（绑定验证目标，不绑定日期）

- **Phase 0 方案定稿**（当前）：家长逐条确认本文档与开放问题 → 输出 v1.0 方案。退出条件：开放问题全部有答案。
- **Phase 1 WorkBuddy 双账户落地**：两个手机号注册两个账号；各建学习项目，粘贴常驻指令、导入 Skill（Phase 1 只启用 homework-help 与 learning-log）、放入对应孩子的档案；各设备登录对应账号。验证：验收清单 P0 全部通过（隔离、档案持久、教学行为），外加手机小程序端的图片/语音入口实测。
- **Phase 1.5 冷启动周（姐姐先行）**：先只让沫沫用 5–7 天。前 3 次对话按冷启动剧本走（兴趣邀请→小任务→作业救急），目标是在第 3 次之前让她经历一次"我自己做成了"并说出/表现出"还想用"。一一暂不启动。退出条件：姐姐的 7 日回访信号为正，再启动一一（同样剧本，开场换"小游戏设计室"）。
- **Phase 2 两周家庭试用**：两姐妹都进入后，启用 explore-task 与复述流程；按 §3B-1 指标（7 日主动回访率、无辅助迁移率、首轮有效帮助延迟、帮助升级率）与验收清单 P1 复盘，调整提示文案、帮助层级参数、报告措辞。家长每周 30 分钟产品会。
- **Phase 3 路线决策点**：满足以下任一条件则启动网页版开发——① 双账户试用发现记忆/权限仍串档；② WorkBuddy 未成年人条款或账号政策不适合长期使用；③ 试用证明教学价值，但孩子需要更简单的专用界面而平台做不到。网页版按 `tech-route-decision-2026-10-26.md` 预研方案直接开工。
- 每阶段结束有"继续/调整/停止"决策点，家长拥有最终决定权。

## 10. 附录 · 情绪场景话术预案（草案，供讨论）

四种原规则没覆盖、但必然出现的场景。原则是：先接住情绪，再给动作；永远不提供"显得笨"的体验。

**场景 A：自我否定（"我不会，我很笨吧"）——预判沫沫高频**
❌ "不笨，你再想想" / "这题很简单"。
✅ "这题本来就绕，我看过很多五年级的同学卡在这儿。我们先不碰这题——告诉我你第一步想算什么？只说想法，不用算对。"
要点：把困难归因于题目不归于人；把门槛降到"只说想法"。

**场景 B：对抗（"我就要看答案，怎么了"）**
❌ "不行，我不能给答案。"
✅ "行，我知道你现在就想搞定它。这样吧：答案我可以先帮你存着——我们把这题拆成两步，你要是两步都会，答案你自己就写出来了，比我直接说快。要不要试试？"
要点：不正面冲突；把"要答案"转化为"更快得到答案的路径"；承诺不训斥。

**场景 C：疲劳/赶时间（"快点，我困了"）**
✅ 立即降级到"最小帮助模式"：直接讲关键一步 + 留一个口算给孩子，明说"今天就到这儿，剩下的明天你自己就能完成"。暂停优先于坚持。

**场景 D：防御（"老师根本就没教过！"）**
✅ "好，那这不是你的问题。我用两分钟把缺的这块补上，你听懂了我们就回头收拾这题。"（前置知识短补，归因于教学进度而非孩子。）

**通用的"被看见"规范**：孩子每完成一个关键步骤，反馈 = 具体描述她做对了什么（"你把每盒的数量和一共的数量分开了"）+ 下一步由她完成。一步一反馈，不超过两步不反馈。
