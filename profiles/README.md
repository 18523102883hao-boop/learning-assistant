# 孩子档案（profiles）

## 两层结构：孩子端只看一层

| 文件 | 谁读 | 内容 |
| --- | --- | --- |
| `current.json` | 孩子端专家 | 只有一个字段 `child_id`，指向当前这台设备上的孩子 |
| `kids.json` | 孩子端专家 | 两个孩子的**最小档案**：昵称、年级、教材、兴趣、朋友名字、进行中的作品、帮助偏好 |
| `momo.json` / `yiyi.json` | **只给家长端** | 完整档案：含家长观察、班级排名、性格描述、掌握摘要 |
| `*.example.json` | 谁都不读 | 示例，用于测试 |

**这条边界是硬的：** 孩子端专家永远不打开 `momo.json` / `yiyi.json`。那里面的「排名三十左右」「嘴上不饶人」一旦进了孩子的对话，就变成了贴标签，正好踩中项目的头号红线。工程附录 §5.2 也要求 child_profile 的最小字段不含排名和家长人格观察。

**朋友名字单独说一句：** 名字放进 `kids.json`，因为「孩子提起朋友时能叫出名字」是设计里明确要求的行为，不给她名字就等于装不认识。但名字**只活在当下那句话里**——不写进学习事件、不进周报、不进任何摘要（验收矩阵 T30）。`friend_hook` 是给伙伴看的用法提示，不念给孩子听。

## 换人怎么切

改 `current.json` 一个字段：

```json
{ "child_id": "yiyi" }
```

改完**新开一个会话**才生效。建议路径：

- 最稳：两个孩子各用一个账号 / 各自一个工作目录，各放一份 `current.json`，从根上不会串。
- 一台设备轮着用：交接前家长改这一行。这是约定，不是技术锁——不设防的情况下，姐姐完全可能被当成妹妹。要知道这个限制，别当成已经隔离了。

`child_id` 是稳定标识：跨新任务、换设备不变。**新建聊天不等于新身份。**

## 学习事件写在哪

`profiles/learning-log-{child_id}.jsonl`，一条一行。已加入 `.gitignore`，不入库。

`learning-log` 只在 `current.json` 明确给出 `child_id` 时才写。靠询问、靠猜、靠孩子自报得到的身份，**本次一律不记**——宁可少一条记录，不把表现记到错的档案里。

## 其他约定

- 档案可更正：孩子或家长指出有误时更新，并保留修订痕迹。
- 掌握情况摘要从 `learning-log` 的学习事件生成，不由某一次对话直接下结论。
- 教材版本未核对前，`curriculum` 里写"待核对"，专家只做跨版本概念辅导。
